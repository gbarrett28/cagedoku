# Spec: Seamless Puzzle Input

## Problem

Loading a puzzle requires the user to save an intermediate file (screenshot or
download), navigate a file picker, then click Process. This is unnecessary friction
for the common case of sharing a puzzle seen in a browser or mobile app.

## Solution overview

Three layers of improvement, in increasing complexity:

### Layer 1 — Paste & drag-drop (Sprint 1)

On the Upload screen:

- **Clipboard paste** (`Ctrl+V` / `Cmd+V`): read the first `image/*` item from
  `ClipboardEvent.clipboardData`, synthesise a `File`, and start processing
  immediately. Works on all desktop browsers without any install step.
- **Drag-and-drop**: the `#upload-panel` becomes a drop target. Dragging an image
  from a browser tab, file manager, or screenshot preview onto the panel starts
  processing immediately.
- **Auto-process on file-input change**: the `change` event on `#file-input` fires
  `handleProcess()` immediately so the separate Process button click is eliminated.
  The Process button is removed; a single "Choose image…" button opens the file
  picker (via `.click()` on the hidden `#file-input`).
- Visual affordance: the upload panel shows secondary hint text
  "or drag & drop / paste (⌘V / Ctrl+V)".
- The paste and drop handlers are only active when the upload panel is visible
  (i.e. `#upload-panel` is not hidden).

`handleProcess` is refactored to accept an optional `File` argument so all three
input paths share one code path.

### Layer 2 — PWA foundation (Sprint 2)

Making the app installable as a PWA unlocks OS-level integration (Layer 3).

- `web/public/manifest.webmanifest` — name, short_name, icons, start_url,
  display: standalone, theme_color, background_color, description.
- App icons: `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`,
  `apple-touch-icon.png` (180×180). Generated by a build-time Node script
  (`scripts/generate-icons.js`) that renders the existing SVG favicon via a
  headless canvas.
- `index.html` — `<link rel="manifest">` and `<meta name="theme-color">` /
  `<link rel="apple-touch-icon">`.
- Service worker — manifest and icons added to `PRECACHE_ASSETS`.
- Install prompt: `beforeinstallprompt` is captured and deferred. A dismissible
  "Install app for quicker access" banner appears at the bottom of `#upload-panel`
  when the prompt is available (i.e. app is not already installed). Clicking it
  triggers `prompt()`. The banner is stored in `localStorage` so it does not
  reappear after the user dismisses it.

### Layer 3 — OS integration (Sprint 3)

Requires the PWA to be installed (Layer 2 prerequisite).

- **Web Share Target** (mobile long-press → Share): `share_target` added to
  manifest with `enctype: multipart/form-data`. The service worker intercepts
  POST `/share-target`, reads the image from `FormData`, stores it as an
  `ArrayBuffer` in IndexedDB (`coach-share-inbox`, key `pending`), and redirects
  to `/`. On page load the app checks IndexedDB, reconstructs the `File`, calls
  `handleProcess()`, and deletes the entry.
- **File Handling API** (desktop right-click → Open with): `file_handlers` added
  to manifest. `main.ts` registers a `launchQueue` consumer that calls
  `handleProcess(file)` with the launched file. Guarded by feature detection
  (`'launchQueue' in window`).
- No UI changes required — both paths feed into the existing `handleProcess` entry
  point.

## Browser support summary

| Feature | Desktop | Android | iOS |
|---|---|---|---|
| Clipboard paste | All modern browsers | Chrome (user-gesture paste) | Limited |
| Drag-and-drop | All modern browsers | N/A | N/A |
| Auto-process on select | All browsers | All browsers | All browsers |
| PWA install | Chrome, Edge, Firefox, Safari 17+ | Chrome | Safari 16.4+ |
| Web Share Target | N/A | Chrome | Safari 16.4+ (installed PWA) |
| File Handling API | Chrome, Edge (installed PWA) | N/A | N/A |

## Non-goals

- URL input (CORS complexity, minimal benefit)
- Screen capture API
- PDF support (separate planned feature)
