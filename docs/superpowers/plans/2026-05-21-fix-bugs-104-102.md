## Task 3 — Defensive guard in `mrvBacktrack`

**Files:**
- Modify: `src/engine/backtracker.ts`

`★ Key insight:` The `search()` base-case validation already checks rows/columns/boxes inline, but it operates on raw Sets and may miss edge cases. This defensive guard re-validates the extracted `number[][]` result before it leaves `mrvBacktrack`, converting any invalid solution to `null` so the caller sees `UnsolvedByRules` rather than a corrupt `goldenSolution`.

- [ ] **Add `gridValid` helper above `cageValid`**

  Insert this function before `cageValid` (around line 82 of the current file):

  ```typescript
  /** Returns true iff the 9×9 grid has no duplicate in any row, column, or 3×3 box. */
  function gridValid(grid: number[][]): boolean {
    for (let i = 0; i < 9; i++) {
      const rowSeen = new Set<number>(), colSeen = new Set<number>();
      for (let j = 0; j < 9; j++) {
        const rv = grid[i]![j]!;
        const cv = grid[j]![i]!;
        if (rowSeen.has(rv) || colSeen.has(cv)) return false;
        rowSeen.add(rv); colSeen.add(cv);
      }
    }
    for (let br = 0; br < 3; br++) {
      for (let bc = 0; bc < 3; bc++) {
        const boxSeen = new Set<number>();
        for (let r = br * 3; r < br * 3 + 3; r++) {
          for (let c = bc * 3; c < bc * 3 + 3; c++) {
            const v = grid[r]![c]!;
            if (boxSeen.has(v)) return false;
            boxSeen.add(v);
          }
        }
      }
    }
    return true;
  }
  ```

- [ ] **Add the defensive guard to `mrvBacktrack`**

  Replace the last two lines of `mrvBacktrack` (currently `return search(...)`):

  ```typescript
  const solution = search(cands, cageOf, cageTotal, cageCells, { n: 0 });
  if (solution !== null && !gridValid(solution)) {
    console.error('mrvBacktrack: search returned an invalid solution — treating as unsolvable');
    return null;
  }
  return solution;
  ```

- [ ] **Root cause follow-up (if the regression test was failing in Task 2)**

  If the test failed before the guard, investigate which path produced the invalid solution:

  1. Add `console.log` before `return solution` in `search()`'s base-case block to print the grid and see which path reached it.
  2. Check whether any Set in `cands` at that point has `.size === 0` (would have returned null earlier) or `.size > 1` (would not reach the base case).
  3. Most likely fix: the `assign()` propagation does not enqueue pre-existing singletons from the starting board state. If two cells in the same row both start as `{6}` (wrong singletons from the rule engine), neither is ever pushed to the propagation queue, so the conflict is never detected before the base case. Fix by adding an initial propagation pass at the start of `mrvBacktrack`:

     ```typescript
     // Propagate all pre-existing singletons from the rule engine before searching.
     for (let r = 0; r < 9; r++) {
       for (let c = 0; c < 9; c++) {
         if (cands[r]![c]!.size === 1) {
           const d = cands[r]![c]!.values().next().value as number;
           if (!assign(cands, r, c, d, cageOf, cageTotal, cageCells)) {
             return null; // starting state is already contradictory
           }
         }
       }
     }
     ```

     Insert this block after the `cands` array is built (line ~65) and before `return search(...)`.
